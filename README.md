## 买企鹅（实验性 PC 后台）

重开源码助手，在任务中选择 **买企鹅（实验性）**，选择电脑客户端/具体实例，填写 **企鹅总只数**（1～999999，必填）后“开始购买”。可从大厅、圣域、精灵之森、成长祭坛或已核实的企鹅数量弹窗开始；若起点是外来数量弹窗，会先取消回到祭坛核对本次资源，不直接购买。不要用空进度替代该账号已有记录。

- 路径：**圣域 → 精灵之森 → 成长祭坛 → 企鹅巢穴 → 最多 → 购买**。按当前弹窗实际单批上限分批，尾批用已核实的最少/最多/±1精确调数；数量表示购买总只数，不是点击次数或保底品质。
- 仅购买企鹅栏；先核验全单预算、单价、币种、库存、数量和总价，预算不足不先部分购买，不兑换/补买祭坛资源，不购买体力、复活或其他商品。所有原有窗口/进程/几何、最小化、帧新鲜度、鼠标接管、STOP和本地历史保护保留。
- 单独保留本机 `penguin/state.json` 与证据。最终购买只发送一次，须独立核实同目标祭坛余额恰好减少原笔总价才计入“已购企鹅”；发送或结果不明不重发，新开始也不能绕过未决扣费。仅调数量、点击购买或关闭弹窗都不算购买成功。
- **验收边界：** 本机 PC 后台已走通导航、数量弹窗、最多及尾批减1；尚未在用户指定实测数量后执行最终扣费，因此购买结果页和多批连续购买仍未实机验收。未知获得物品页会停在等待处理，可手动关闭后继续原任务核对余额；不会盲点关闭。MuMu 未接入此模式，旧助手/worker不会热加载源码；v1.4.10预览包包含此实验项，最终扣费及多批实机限制不因打包解除。

## 新号主线 / 新手教学（开发验收中）

仍选择“推进主线/剧情关卡”，不新增账号识别门槛或前台模式。已接入“第6时代Episode”地图、纯剧情节点、无AUTO的故事固定队伍准备页、欢迎信与完整免费奖励关闭；已观察到的固定队伍可在当前角色/生命/波次、第一基础技能可用光框及敌方目标均核实后执行基础攻击。教学有明确跳过时优先跳过，未知引导文字、未支持的角色/控件和弹层不靠连点处理。

- 教学动作必须双新帧核对，截图与发送意图先落盘；同页不连点，未知/加载和重启不会自行解锁防重。
- 不点击魂燃、神兽或付费复活；不购买/兑换体力，不自动重试失败或结果不明的关卡。教程抽卡/装备等尚须按实际画面逐项接入，**没有宣称全新手流程已支持或前三章已验收**。
- 真正换新号须明确关联新号自己的独立记录，旧号的失败、入场、通关及证据完整保留；不能切换到空记录绕过同一账号的历史。
- 同run维护重载须核实原worker已退出、原请求/状态/停止报告哈希及目标/设置一致，保留当前原始入场链；维护不产生重开许可。已证明只被免费章节领奖截获、故事未开始的同一零体力UI流程可接续一次，不再逐关索要重试许可；须有通知点→该档已领取勾与完整原动作链。其他真实重开仍须具体授权，原sent不能改成not_sent，失败/不明不能重用。
- 点击消息sent不等于游戏接受，更不等于通关。统一主线的零体力故事入口新增响应核验：同run/原sent/证据、当前未完成节点、仍锁定的后继关和独立双新帧均核实且没有实际剧情/战斗/其他输入时，原链最多补发2条入口消息，不再因一次丢点击逐关索要许可；每条补发预先留证并落盘，失败/不明不重用。出现实际剧情/战斗即停止补发，通关仍须独立证据。耗体力战斗、剧场门票和旧归档不使用此规则；PC/MuMu范围及实机结果见CHANGELOG。

## v1.4.8 画面稳定与截图过期恢复

PC画面若在规划前因识别耗时过期，会持续丢弃旧帧重新读取；明确未发送的普通地图/辅助选队导航也可重新取图规划。窗口/进程/几何异常和已写入意图后的异常仍不能借此自动重放。结算要求两处完整标签与唯一、高置信度的右下确认，未知确认不会穿透到底层页面。主按钮运行/等待时保持白字，避免系统禁用色造成灰字绿底。

v1.4.8预览包包含这些修复。当前已打开的助手和工作进程须重新启动才能加载；建议在当前战斗完成后停止，再关闭并重开助手。没有清空历史或自动补记本次关卡。具体验证范围见 `CHANGELOG.md`。

## v1.4.5 启动、窗口与继续修复

每次打开默认“自动识别”。`Assistant.cmd`、`Start.cmd`、`PCStart.cmd` 使用同一界面，后两者不再强制客户端或覆盖上次任务。PC普通最大化不再要求精确16:9，铺满窗口时按实际客户区分别换算横、纵坐标；有明确居中黑边时自动扣除并还原点击偏移。运行中缩放会丢弃旧帧，确认后重新取图。

普通深渊先按1600×900进行OCR，再把文字框映射回原客户区，修复小窗口准备页漏字；完整识别当前准备页后可接续，旧入场和通关记录仍禁止重复。

本次最大化验证是坐标回归及原截图缩放回放，尚未实测真实最大化战斗；PC仍为实验性。更新后须关闭旧助手并重新打开。

## 日常入口

双击 **`Assistant.cmd`**。启动器会自动申请标准管理员权限，系统UAC由本人点“是”；已是管理员则不重复申请。

1. 打开已登录的游戏；选择客户端及具体实例。只有唯一目标时自动填入；多个目标必须手选，运行时不会擅自切换。
2. 选择“推进剧情关卡”“普通深渊”或“圣女3-7”。MuMu 使用 ADB；PC 只用后台窗口消息（实验性），不提供前台模式。
3. 无需设置次数，直接点击“开始推进”。不读取账号或服务器，不进入账号页，没有“仅观察”开关或额外勾选。请自行在游戏中准备好队伍和原生自动战斗；默认持续推进，不设关数或层数上限；首次使用后台模式建议在旁观察，用暂停/停止控制。
4. 暂停保留当前会话，点击“继续运行”重新截图；停止不会关闭游戏或清空历史；进程退出后再次点“开始推进”即可从当前画面继续。

窗口按 Windows 可用工作区限制大小，内容可滚动，开始/暂停/停止固定在底部；不缩小字体硬塞内容。

`Start.cmd`、`PCStart.cmd` 以及旧深渊助手的本机 `Launch.cmd` 都是同一界面的入口别名，不是独立软件。原维护 CLI 保留用于只读检查、人工补过核验等高级维护，不用于日常分开启动。

- “圣女3-7”用于时间之书《圣女追悼文》。不能从大厅自动导航到该支线；从大厅启动时，请先手动进入“支线 → 时间之书 → 圣女追悼文”的地区总览或关卡地图；任务从当前进度推进，到3-7成功结算后只选择3-7反复刷，不进入3-8。它不会在大厅误把Episode主线当作圣女支线。
- 每次入场前核对准备页的完整关卡编号，保存独立意图；蓝线出口只在明确识别后点击右侧，不点“重新进行”猜测通关。原主线历史与剧情按命名空间分开保存。
- 唯一重复授权是成功结算后的圣女3-7；其他关卡、战败局、结果不明的入场都不重复。体力不足在队伍页等待自然恢复，不购买、不兑换；容量等未知业务弹窗仍需处理。
- 当前为实验性兼容，具体实机范围见 `CHANGELOG.md` 和 `docs/STORY_VALIDATION_2026-11-03.md`，不承诺所有历史支线布局都已支持。

## 高频免费提示

已核实的“教学已完成”免费通知（包括完整未翻译键）按每次出现识别关闭，后台剧情文案里的“确认自己”等不会误当按钮。每次双新帧核实本帧唯一“点击关闭”，保存独立关闭记录，明确消失后可处理下一次相同提示；不再按整个run或关卡永久锁死。同一未消失提示有界等待/补发，不连点底层。未知错误键、任意确认、购买/资源/容量/战败弹窗不会通用点击。关闭通知不代表关卡通关。 若通知拦截的是同run原唯一零体力故事入口，只有原入口、每条关闭发送和独立消失证据全部对应后，才在原有界响应链上继续等待/补发；不会因正常关闭通知把流程误报为“已经播放”，也不会只凭提示名称放行其他输入。

## 持续推进

主线和普通深渊不设人为次数上限，界面无次数输入，不会到3关或30关自动结束；旧配置中的limit会被忽略，并在下次正常保存设置时移除。按暂停/停止，或出现战败、资源不足、容量/窗口/画面等需处理情况时才暂停或停止。取消计数上限不代表允许购买、复活或重复入场；这些规则不变。

## 提速与弹窗

- 主线/剧情、普通深渊、月光剧场和实验性次元探查按0.25秒目标周期取新帧；耗时计入周期，旧 `fast_mode` 不再放慢统一调度。新页面校验通过即推进，不等整屏加载；同页防重复发送、深渊层数/次元目标的跨帧核对仍保留。网络重连及自然体力恢复保留原退避，暂停/人工接管/等待用户处理不自动输入。
- 预览先缩到560×315再编码，避免重复保存全尺寸预览；识别仍使用原标准画面。
- 单独识别无确认按钮的Rank升级全屏提示，以及“账号升等、行动力上限已提升”的免费点击关闭弹窗；故事奖励按弹窗“点击关闭”处理，不点背后地图。
- 后台短暂黑帧只重取画面、零输入；超过10秒进入等待处理，不抢焦点、不回退到前台。
- 装备/神器/英雄容量、体力和未知确认框进入“等待处理”，用户处理后点“处理后继续”；不误判战败、不卖装备、不扩容、不兑换。

## 地图完成判定

- 缺失/读不到右侧星级记为未知，不当成已通关；显式通关星级标签旁的0～3星文本可作为补充证据，1星也算通关，0星不是。信用等级的菱形、英雄稀有度与章节总星数一律排除。无标签的未知星形布局不保证识别，不会据此冒充完成。
- 左侧通关标记不再以少量绿色像素为准，而检查徽章轮廓、勾形和节点绿环；所有可见关卡行都检测锁，不再仅检查当前选中行。
- 当前关只有入场记录、没有通关证据时会显示具体原因，不能自动假设成功并点下一关，也不会在地图和队伍页之间循环。原记录不删除，不回看旧关。

## 后台模式边界

- MuMu 的输入与截图发给已绑定 Android 实例，不移动电脑鼠标；模拟器内仍需保持授权游戏为前台应用。
- PC后台使用 `PrintWindow` 取客户区、`PostMessage` 发送窗口消息；不调用 SetForegroundWindow/SetFocus/AttachThreadInput，不伪造 WM_ACTIVATE，不注入、不读写游戏内存，不自动回退到 SendInput。
- 本机已验证 GLFW30 窗口的无焦点导航。接口返回成功只说明消息已投递，必须由后续截图验证游戏实际变化。
- **PC后台不支持最小化**；任意遮挡/长时间挂机/拖动/CG长按/维护后的兼容性均不能视为已完整验收。
- 进程寿命、窗口身份、尺寸/DPI、截图新鲜度、STOP和任务校验继续生效；窗口或画面不确定即停。

## 安全与隐私

- 只允许正常关卡入场消耗；不购买/兑换体力、不复活、不重试失败关卡、不改队伍或养成。
- 仅上方普通深渊，禁止下方挑战模式；未知确认框不盲点。
- 主线保留全部 attempted/completed/last_cleared，旧 active 完整归档；深渊入场前另行持久化意图，结果不明不重复开战。
- 一个界面只运行一个任务，并与旧主线共享进程锁，避免双写或双客户端同时输入。
- 配置、账号历史、截图、OCR、日志、设备信息、本机识别图块和第三方运行库均不提交 Git、不上传。
- 使用现有本机 Python/Tk 与工作运行库，没有为本次整合下载内容或修改代理、安全设置。

已有 v1.2 离线分享包与 v1.1 覆盖更新补丁。运行库/资源/GUI 自检不等于跨机器实际跑关，四种组合的完整实机矩阵仍未验收。换账号不再自动识别，必须使用对应原进度，不要复用其他账号目录或清空历史。

## 文件与测试

- `assistant_app.py`：唯一图形界面；`assistant_config.py`：选择/迁移/工作区策略
- `assistant_worker.py`：单任务执行、暂停与停止；`assistant_transport.py`：共享客户端接口
- `pc_message_backend.py`：独立的显式后台消息适配；`pc_backend.py`：前台兼容/显式窗口授权适配（旧维护接口仍保留）
- `runner.py`：原主线状态机；`abyss_core.py` / `abyss_templates.py`：普通深渊状态机与本机识别图块
- `.local/assistant/`：本机设置、会话与日志；原主线状态目录仍原位引用，不复制成空记录

离线测试不产生游戏输入：

```powershell
py -3.12 -B -X utf8 run_offline_tests.py -v
```

真实素材不分发。`EPIC7_PRIVATE_FIXTURES`、`EPIC7_PC_FIXTURES`、`EPIC7_ABYSS_FIXTURES` 可指向各自的私有回归目录；缺少素材时明确跳过，不当作通过。工作运行库路径沿用已有 `.local/python-path.txt`；GUI需包含Tkinter的本机Python，可用 `EPIC7_GUI_PYTHON` 指定。

详细验证见 [统一与后台输入记录](docs/UNIFIED_ASSISTANT.md)，历史更新见 [CHANGELOG](CHANGELOG.md)。
