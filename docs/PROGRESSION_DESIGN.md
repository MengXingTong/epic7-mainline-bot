# 推进优先的证据与恢复设计

## 2026-11-07 最新原则：当前游戏事实优先（覆盖下文旧因果门槛）

统一主线已知页面采用一次当前观察→当前控件业务判断→必要意图持久化→输入，不为了同一控件重新截图、全屏 OCR、强制两帧一致或局部双读。原全屏 OCR 缺少字段时可在同一原图的原字段补读一次；这不是发送前重截图或重复投票，弱/残缺读数不猜测。

主线 `progression_facts.py` 的判断独立于输入日志：

- 当前同章同分支原节点有明确通关勾/合法关卡星级，或原地图已锁定的下一关当前解锁，才能新增旧节点完成记录。
- 原节点裁切时仍读当前像素中的通关徽章形状，不再要求原 `sent`、播放、领奖关闭及逐条切页链无缺口。
- 当前已明确选中后继未锁节点，可完整归档旧 active 后继续该新节点；看不到旧节点完成事实就不写旧节点 completed。
- 结算确认/免费奖励关闭是导航动作，不是完成权威。只记录当前结算观察，回地图后按真实节点状态完成。
- 只有当前明确战败页产生 defeat。发送记录、消息未响应、长时间战斗/加载和未切页均不产生失败；结果暂缺继续观察，不锁存为需要用户再次许可的失败。
- 历史点击记录继续保存，用于审计和防止资源入场重复，不再冒充游戏接受或完成。未知/失败的体力入场不能自动重发；不因结果等待解除防重复。

跳过仅使用本周期唯一精确控件；发送前再取一次像素，仅核对该易变控件（确认页同时核对确认/取消），不重复整屏 OCR、不刷新旧 OCR 时效。字形消失或变化时取消旧计划并自动重取图，原始/即时证据和取消原因独立保存，取消观察不是一次实际输入。保存截图和小型动作意图后发送，不在识别和发送间重写全部旧历史。其他关键业务状态仍在输入前成功保存；state.json 使用完整无损紧凑 JSON，未改变任何字段值。战斗/加载的相同展示状态不逐帧重写大历史，首次缺项诊断仍立即留证落盘；等待计数定期检查点保存。

窗口/进程/几何、最小化、帧时效、实际鼠标/修饰键接管、STOP、资源/付费/容量和关键写盘失败仍有各自的执行保护。它们是“不应发送这次操作”的原因，不是战败证明。未知画面持续零输入。

下文因果链实现仍保留供历史审计/旧离线素材测试及特定免费入口响应许可使用，不再成为统一主线判定完成的必需门槛；未宣称所有任务模式、PC和其他布局已经实机验收。


## 目的与本次落地范围

脚本的正常目标是持续推进，不是找到任意不确定性后等待用户重复点“继续”。本次将**同 run 纯剧情结果、游戏原生换章与已知地图身份补采**接入可审计的因果里程碑模型。它不是所有任务模式的完整重写，也不是通用自动重试或未知弹窗处理器。

## 三条互相独立的判断轴

1. **当前画面与当前控件是否可信？** 已知页面按当前控件、置信度、窗口/进程/几何、资源与帧时效核验；不等待背景动画静止。未知画面/弹层当前帧始终零输入。
2. **实际操作产生什么效果？** 普通观察不等于操作；输入意图、消息发送、游戏接受、独立结果是不同事实。操作在统一语义边界归类，未知操作不能自称为免费动作。原 attempted / entry_dispatches / sent 不回写成 not_sent，不因维护而清空。
3. **哪些推进里程碑已被独立证明？** 剧情入口消息 → 真实播放 → 完整免费剧情奖励 → 关闭 → 返回地图。`progression_evidence.py` 只折叠证据，不执行输入或授予重开许可。自然播放和跳过使用相同结果契约。

## 观察不能抹掉进展

加载、结果过渡、短暂识别为空、只读留证与跳过控件复核属于观察；中间出现一次这些画面，不把已经确认的播放/奖励回退成“未开始”或“链已断”。这不是一张允许特定关卡/标题/加载文案的页面白名单；不认识的历史观察也不自动变成未知输入。

反向证据与实际输入仍然有约束：战败、与纯剧情冲突的战斗/结算、资源或容量阻断、外部导航，以及不明操作、返回、拖动、额外打开入口不能被忽略。当前未知弹窗也不能因为历史里程碑存在而点穿。

所有结果仍须独立当前证据：裁切剧情节点需要原始唯一发送链、同 run 游戏接受记录、目标绑定、原始截图哈希、准确的章节/编号/相邻锁定关系，以及原节点的绿环和内部通关勾。选中了下一关、章节星数、发过消息、关过奖励都不能单独算通关。原生换章另需已解锁下一章首节点与后继锁定证据，不能由人工换章动作替代。

有界入口响应补发若已在原链被游戏接受，结果校验消费**既有回执**，逐条核对来源事件哈希、消息状态、双帧/目标绑定、像素证据与时间顺序；不因为有合法补发就否认实际结果，也不生成新补发权。免费通知绕行逐条复用已有独立消失回执，不能只白名单关闭动作名称。

## 决策分类

| 情况 | 行为 |
| --- | --- |
| 当前控件和业务证据完整 | 立即执行当前合法下一步；不等整屏静止 |
| 已观察播放、当前结果证据暂缺且无矛盾 | `waiting_evidence`：继续新帧只读核实，证据齐全自动推进；不要求重复点继续 |
| 当前未知画面/过渡/黑帧 | 零输入观察，窗口/几何错误不按黑帧重试 |
| 来源/哈希/目标绑定矛盾或未知实际输入 | 明确完整性 attention，展示真实缺项；不冒充普通等待 |
| 体力/容量需要人处理 | 可恢复 attention，不购买、不扩容、不复活 |
| 真实战败或结果不明入场 | 保留原链，不重开关卡 |

观察等待不创建入场记录、不写 completed、不释放 active、不清除防重、不自动消费资源。等待诊断按原节点的不同缺项各留一份独立截图并累计观察次数，避免逐帧/来回切换原因造成证据膨胀；所有已创建证据保留。关键状态/证据/意图写盘失败仍直接失败，不降级为观察等待。

## 回归要求

- 以性质测试验证：在同一合法结果链任意位置插入任意数量的无输入过渡观察，已确认里程碑不变。
- 自然播放/跳过、重复观察、同一时钟秒内上一关事件、展示文件回退、合法已接受补发均不得变成额外入场。
- 不明动作、伪造 effect、错节点、错窗口、失败/不明补发、像素与来源哈希改变、阶段倒退仍拒绝认领结果。
- 证据暂缺 → 多次只读等待 → 独立新证据齐全后推进，整个过程无需人工 resume；原 attempted / sent 完整保留。
- 当前未知弹窗、付费、容量、战败、窗口/新鲜度、STOP和关键落盘错误的原有高优先级保护不能回归。

新增功能应扩展明确的动作效果/结果证据契约，而不是在结果层列举每一种过渡动画，或为某个章节不断追加授权特例。未经实机的任务、客户端及分辨率不因通过离线测试而宣称已支持。

## 地图身份与截图时效

章节标题不作为固定场景白名单。身份由 Episode、数字章节、可选字母分支、节点编号组合；主章节保持原 key 字节兼容，分支必须有独立 key，所有同章比较、裁切结果、原生换章候选与防倒退排序均使用完整身份，不能把 8S 的节点当成 8 章同号节点。

已识别为地图但当前身份缺项时，进入同一只读采证机制而非 20 秒后人工锁存。缺少置信度、存在多个标题、几何不符、编号/蓝环不足都不会产生入场意图。字段恢复后按完整业务链继续。

规划前帧时效检查适用于 MuMu 和 PC，发生在入场/持久意图生成之前；PC 仍额外核验自身目标绑定。普通非入场操作若在最后发送前发现过期，只废弃该计划并重取图，不升级为人工 client_input attention。TapNotSent 的后台按下前接管证明仍仅用于真正提供此证明的 PC 后端，不能把 ADB 普通异常伪装成 not_sent。

## 界面进程生命周期

“业务已停止”不等于操作系统进程已经退出；stdout EOF 也不等于退出。读取线程先 wait 回收子进程再发布退出事件，UI 另按进程实际退出状态兜底核对并解除按钮锁存。尚活着的写入者不能因为先收到停止/EOF 状态而允许再次启动，旧 PID 的退出事件也不能清除新 worker。暂停/停止在自动采证状态下继续可用。

## 持久准备不是实际发送

统一 worker 的零体力故事与标准体力战斗首次入场走同一条管线：先将原 attempted、唯一 reservation、响应上下文和准备计划完整落盘；再独立截图，重新验证同一窗口/几何、关卡/标题、当前入口、费用/库存与队伍模式；最后只写小型独立调用意图并调用输入后端。最后一帧之后不再插入整份大历史写盘，避免持久化本身把已核实控件拖成过期帧。

准备完成但尚无调用回执时，临时读图不足只重取图，复用原 reservation 完成首次实际发送，不追加 attempted、不改 not_sent。调用意图一旦存在，发送失败/不明不能重新消费；明确 TapNotSent 仍沿原规则单独记录。预备状态本身不能被当作游戏已接受；只有实际 sent 的入口响应链才观察接纳。关键调用回执写盘失败始终零输入并失败。

如果尚未调用的本地计划已被用户或其他实际流程接走，当前又正向识别到剧情/战斗/结果，则不能让一个旧准备状态阻断已知免费“跳过/关闭”流程。在当前画面策略下，保存未调用证明和当前截图、完整归档原 active、保留 reserved/attempted，不冒充 sent、不拿旧计划认领这场结果；之后继续处理当前已知页面。已经有调用意图或发送不明的计划不能使用这条路径。旧归档准备不因新开始自动恢复，也不把所有 reserved 批量解释成未发送。

## 完整行标签而非 OCR 第一块

关名可能被 OCR 拆成“编号+标题前半”与“标题后半”。地图识别按本帧同一基线、逐块置信度、紧邻且不重叠的文字框组装完整标签，原 OCR 和每块来源保留。不能只放宽标题相似度、拿短前缀代替完整关名，或拼接别行/别列/弱字/重叠候选。地图→辅助→队伍仍比较完整的原关卡来源。

## 已核实聊天侧栏恢复

仅完整当前标题和空编辑区/已知连接提示核实、当前侧栏局部像素仍一致时，预先落盘本次原生关闭意图。发送成功只说明关闭消息已发出；必须在后续独立已知页面确认侧栏消失，才结束本次出现。原生返回不是聊天输入，不点底层、不新增/解锁入场，也不代表完成。每次出现独立编号，单次最多两条有间隔且重新核实的关闭消息；失败/不明结果不复用。遮挡期间的未知/资源/容量/战败及窗口保护继续优先。


## 容量拒绝、继续指令与地图重建（2026-11-09）

容量满不等于战败，入场消息sent也不等于游戏已经接受。完整原生容量弹窗若与原唯一未接受入场对应，只记录该次独立拒绝，不删除原attempted/sent或把它改写为not_sent。同一仍未消失的拒绝弹窗重复出现保持幂等，不凭重复截图制造新的入场许可。

用户在attention后点“处理后继续”，控制层返回匹配当前run的新命令回执；主线单独落盘拒绝ID/哈希、原入场哈希与本次继续命令。继续不创建新run，不授权未知结果/战败重试，也不沿用整理前的坐标/地图链。每次新拒绝需新的继续命令；每次资源入场发送前消费相应继续记录，发送失败/不明/未发送均不重复使用。

队伍/辅助页缺地图链、地图链属于另一run或已过期时，已知完整页面可先进行有界免费原生返回。返回意图、发送结果、后续独立页面观察各自保留；不把返回sent当地图重建成功。只有当前地图原关完整身份、蓝色未通关节点、锁/下一关约束与唯一免费准备入口核实后，才能重建地图链；完整准备页还需再通过原关名、单次入口和资源校验。旧地图链完整留档，不延长120秒有效期，过期当前帧不建立新地图凭据。

此路径只解决可证明的容量预检拒绝和免费返回死等，不自动整理/出售/扩容，不恢复已接受的资源入场，不认领外来战斗；未知弹层、教学、付费/容量/资源、窗口/进程/几何、帧新鲜度、STOP与关键证据/写盘保护不降级。代码回归使用生成页面及伪后端，不据此宣称新实机验收。
