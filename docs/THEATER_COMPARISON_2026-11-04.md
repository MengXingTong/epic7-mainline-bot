## 比较与取舍

| 参考包变化 | 本项目处理 | 原因 |
|---|---|---|
| 月光剧场列表、门票确认、指南与剧情流程 | 新建 `theater_core/directory/vision/journal/worker`，接入统一任务与启动参数 | 原包直接在 worker 中循环，缺少按剧目/季/集数的持久化防重 |
| 剧情回放/记录/暂停条、战斗图标模板 | 提取两个小图标并去元数据重编码，限定区域识别 | 有正向播放依据；战斗图标优先于剧情条，战斗期间零输入 |
| 淡入全黑最多等待五分钟 | 扩展共享取图函数的可选预算，剧场用 300 秒，原任务仍用 10 秒 | 只重取截图；窗口、进程、几何变化和最小化不作为黑帧重试 |
| 每 0.2 秒翻页，OCR 0.8 秒更新一次 | 按用户后续要求改为剧情点击目标间隔 .05 秒、按下 .01 秒；每次新截图重新 OCR 和模板识别，一帧最多一次点击 | 截图/OCR/留证耗时计入间隔，慢帧不再额外等待或补发积攒点击；实际频率可能低于20次/秒，不复用上次 `story` 分类 |
| 任何未知页默认当剧情连点 | 不采用 | 未知页、过渡页持续新帧观察且零输入；未知确认等待处理 |
| 单独 CLEAR/VICTORY 点击中心 | 不采用 | 单独 CLEAR 只观察；剧场战斗图标和当前明确“点击继续/轻触继续”同时成立才继续，不记观看完成 |
| 点击门票确认即增加已看集数 | 改为独立播放证据 + 相同剧目对应集的明确已观览标记 | 扣票与操作发送成功都不是完成证据 |
| 从主线启动自动切换剧场/深渊 | 不采用 | 尊重用户所选任务，防止主线任务意外消耗剧场门票 |
| `reopen_count` 放行结果不明的深渊入场 | 不采用 | 与保留原尝试、防重和战败不重试冲突 |
| 恢复次数上限、保留前台模式 | 不采用 | 本项目已明确取消次数限制、移除前台输入 |
| 宽松亲密度确认/找不到控件点中心 | 不采用 | 本项目已有更严格的前景关闭/底层结算证据链 |
| 重复启动给出提示 | 吸收 | 第二次启动明确提示回到现有助手，避免静默退出；不建议结束全部 pythonw 进程 |
| 顶部插画、应用图标 | 未引入 | 属于视觉定制，不改善本次执行流程；保留现有可滚动界面 |

本项目已有的鼠标让行、新鲜度、后台窗口类与几何守卫、入场发送区分、日期变更通知、旧版支线、纯剧情节点及已知页面优先级继续保留。没有用旧分支覆盖整个 worker、传输层或历史。

## 使用及记录

1. 更新后重新打开助手，游戏手动进入已解锁的月光剧场列表；选择 PC 实例和 **月光剧场（实验性）**。
2. 实际目录以同帧剧场标题、左侧完整集数和剧目大标题、右侧唯一金色选框及蓝色选中季数共同确定身份，右下角需唯一“进行观览”及明确1张成本/足够库存。后续行的“无法观览”不阻挡当前集；当前集锁定仍停止。身份不明、多个候选、低置信或陌生布局等待处理。
3. 首次观览前落盘截图、OCR、原尝试和发送意图。仅在同一运行的列表链有效、当前中央确认唯一、文案明确只使用一张剧场门票时确认。不买票、不兑换、不接受额外费用。
4. “观览指南”需要完整标题、不可跳过说明、是否开始观览及本帧确认；与扣票分开留证，不再次计票。
5. 剧情控制条完整时翻页，战斗期间只等待。可以接续当前已识别的剧情或免费指南，但不补写旧入场或虚增已看数量。
6. 只有本轮拥有的入场、独立播放证据、同剧目同季对应集数的明确已观览状态齐全才计完成；实际目录要求同一行“完成”及V形绿色勾。本集明确完成后，可点同季可见且未锁定的新N+1行，再从新详情完整核验；也保留明确下一集按钮的旧布局。仅变成 N+1、返回列表或看到 CLEAR 都不替代完成证据。
7. 移动或缩放窗口会先停止输入；用户点“处理后继续”后才接受同一HWND/PID/进程寿命的新几何，丢弃旧帧重新截图。暂停或处理资源提示期间移动也可按此恢复；更换实例、进程替换、最小化及发送不明的旧观览不会因此放行。

原主线 `state.json` 保持原位；剧场记录位于原进度下 `theater/state.json`，注册标记保存在上一级 `theater-registration.json`，完整截图和 OCR 只保存在本机 `theater/evidence`。删除/损坏已经登记的剧场记录会拒绝重建。显式新开始完整归档旧 active，保留 attempted/completed/last_cleared、发送记录及证据。新目录按季区分身份，同时检查旧无季数的键，不能借此绕过旧尝试。只有后端 `TapNotSent` 明确证明按下尚未发送，才在显式继续后重新核验；普通发送异常保留未知状态，不重放。

## 验证与边界

本次验证使用合成 OCR、图标嵌入/缩放、临时进度及模拟窗口输入。另只读检查本项目本机运行日志、证据和当前画面：实际《没落大地》第1季第8集目录保存画面离线识别出5/6/7完成、8选中、成本1张/库存11张，后续9/10锁定；当时的当前战斗画面识别为战斗等待。没有实际运行参考包或导入其账号进度，没有发送真实游戏输入、扣票、改写实际进度、恢复原任务或发布安装包；真实素材继续只保存在本机。

PC 后台及月光剧场均为实验性；MuMu 剧场暂未接入。压缩包未附完整剧场列表、门票、指南和观看完成页截图，文档所称原分支实机通过不作为本项目通过。用户提供的实际目录布局已离线回放，真实票券确认文案、整集观看、多场战斗、完成后返回目录/下一集与跨剧目切换尚未实机验收；缺少明确完成标记、未核实身份或未知 UI 时保留证据并等待处理，不能保证现有游戏每种布局都可自动连续观看。

离线验证结果见本次 `CHANGELOG.md` 的 Unreleased；真实整集验收仍待进行。


## 2026-11-05 补充：原 run 维护载入源码

遇到已确认的程序识别误判时，不必为了载入修复而以新run归档未完链。维护人员在用户明确授权后，先通过原助手停止工作进程，等状态确认为stopped、原进程退出，再正常关闭旧助手；从标准入口显式传入 `--resume-run <原32位run编号>`，可重用同一request和run目录。该路径只面向实验性PC剧场的await_guide/story阶段；原目标、原进度、无STOP及所有本run发送结果必须可核实，否则拒绝，绝不回退普通Start。新进程重新取帧、执行窗口/寿命/几何/鼠标守卫和独占进度锁；原attempted/completed/entry_dispatches/active/证据均保留，既有sent或未知确认不会获得重发授权。标准UAC流程保持，不代点或绕过授权。

这不是自动热加载，也不是让旧attention自动继续。重载前后的真实独立完成、实际票数和发送确认数仍须分别核验；过程中的播放或日志不能算刷完门票。
