# 电脑客户端使用说明（STOVE / Steam，实验性）

## 当前推荐入口

自行完成登录及服务器选择后，在大厅或已知任务页启动 `Assistant.cmd`，选择“电脑客户端”及具体实例、任务，关联对应原进度后开始。统一入口不读取账号字段、不导航账号页，也不要求把游戏置于前台。Steam实例显示“Steam 桌面端（实验性）”，STOVE实例显示“STOVE 桌面端（实验性）”。支持的精确游戏文件名为 `EpicSeven_Steam.exe` / `EpicSeven.exe`；不操作Steam启动器或覆盖层。

两种渠道共享后台PC适配与原进度规则，不因Steam兼容初始化另一套账号历史。保留窗口/PID/创建时间/准确路径、`GLFW30`、几何、最小化、帧新鲜度、STOP、资源和关键持久化保护，不回退前台输入。Steam仅完成本机后台只读发现/截图/OCR验证，实际游戏输入和完整任务仍未验收，详见 `STEAM_VALIDATION_2026-11-09.md`。

以下为**旧版 CLI 历史维护流程**，不代表当前统一界面的启动门槛；不建议日常使用，不为Steam宣称原生输入已验收。

## 日常使用：进游戏 → 双击启动

1. 手动登录《第七史诗》，停在**大厅或主线地图**。
2. 双击项目中的 **PCStart.cmd**，在提示的 7 秒内把游戏窗口前置。
3. 首次使用会要求一次 `Y`，确认实验版风险和历史归属。之后同一角色的正常启动不再询问。

**不需要选择服务器、填写账号编号、填写游戏安装路径，也不需要手动打开账号信息页或修改 JSON。**
程序自动查找唯一的 EpicSeven.exe 游戏窗口，在已识别的菜单中短暂打开账号信息、连续读取两次当前服务器/编号，再返回地图或大厅。它读取的是你已经登录的角色，**不会切服、换号或代为登录**。

> 启动流程已实现并完成离线回归，但自动菜单导航和原生截图/输入的完整实机验收仍未完成。当前不是稳定挂机版；不要把模拟测试或桌面工具现场操作误认为原生脚本已经验收。

## 四个入口

| 入口 | 行为 |
|---|---|
| PCStart.cmd | 正常启动；首次确认后，正常启动不再要求输入确认短语 |
| PCCheck.cmd | 只读检查游戏窗口与截图；无需打开账号页，不点击、不按键、不入场、不修改进度 |
| PCResume.cmd | 明确恢复安全暂停；需要一次 Y；不绕过战败/未结算记录 |
| PCStop.cmd | 向原进度目录写 STOP；不依赖游戏正在运行，不关闭游戏 |

终止状态或用户 STOP 不会被普通启动自动解除。战败/未结算的 active 仍会拒绝入场，不通过删除历史或新建空目录恢复。人工补过仍须核实原关卡绿色勾并补记。

## 首次运行环境

分享包如果含 `python/python.exe`，入口直接使用。源码版需要先准备 Python 3.12 x64 和项目依赖；这属于一次性运行环境准备，不是每次开刷的账号配置。

公共入口依次使用：项目内置 Python、项目 .venv、本机已保存的运行库位置、系统 Python 3.12。不自动下载游戏、修改全局代理或安装输入驱动。必要依赖下载仍通过 install_dependencies.py 先直连，直连失败后才回退代理。

## 账号与进度自动管理

- 本机偏好与自动生成的运行配置在 `.local/pc/`，默认不发布；无需用户手填服务器/账号/路径。
- 已有 `.local/pc/preferences.json`、旧 config.pc.local.json 或项目内 state.json 时，优先复用它指向的原历史。已登记目录丢失、损坏或存在多份无法区分的进度时停止，不创建空历史替代。
- 真正首次使用、没有任何已登记/旧版进度时，只有明确确认并连续核实当前账号后，才在 `.local/pc/profiles/` 建立该角色的首份记录。记录中的通关关卡不凭空补造，地图绿色勾仍逐关校验。
- 已绑定历史与当前账号不一致时拒绝启动；不会自动换绑或把别人的历史套用到新角色。
- 同一账号在 MuMu/PC 间切换必须使用同一份完整历史。已有 MuMu 进度位于其他目录时，需要维护者做**一次迁移关联**，不是让普通用户反复填写配置。不要把一份包含进度的本机目录复制给别人当成公共分享包。

## 窗口和分辨率

- **不要求全屏**。使用实际游戏客户区、窗口原点和 DPI 反向映射输入。1600×900 只是内部识别坐标，不是用户必须设置的显示器分辨率。
- 默认 16:9 客户区，最低 640×360 **物理像素**；建议普通窗口 1280×720 或以上，提高 OCR 可读性。过小、非标准比例、失焦、遮挡、移动/缩放或不可读时暂停。
- 必须前台可见，不保证最小化、后台或用户同时操作时运行。不自动抢焦点。
- 离线矩阵覆盖 640×360 至 3840×2160、96/120/144/168/192 DPI、正/负多屏原点；不是每种显示器的真实游戏验收。

## 安全边界

- 启动前的有限导航只能点已识别的菜单/设置/账号信息标签；不会因此获得关卡入场权限。资源提示、登录/认证、战斗、失败和未知弹窗均不处理。
- 导航需要与本轮截图一致，且一帧只点击一次。相同导航画面不重复点击，最多五轮，不无限尝试。
- 正式输入仍要求新鲜且匹配的账号/窗口/进程证明、已有进度绑定、共享进程锁，以及地图 → 辅助 → 队伍验证链。
- 不兑换或购买体力、不复活、不重打已尝试/已通关关卡，不强化或消耗英雄装备。
- 无法读取服务器/编号或识别菜单时安全停止，不能以简化界面为由猜测。

## 高级维护入口

旧 pc_launcher.py 和 config.pc.example.json 保留，用于显式维护、只读账号校验及人工通关补记；不是普通用户的默认启动方式。

人工补过维护流程仍需精确核对原 active 的绿色通关勾，通过 state_tools.manual_clear 保留原失败 attempt、旧证据与所有历史，再续跑。不要手改或清空 state.json。

## 已验证与尚未验证

- 已完成：离线安全护栏、启动编排与假窗口测试；私有 PC 地图图像的蓝/绿节点和导航图标识别。
- 另有通过桌面工具现场监督的一次 PC 新关入场、剧情跳过、自动战斗、FAILED 失败结算记录。这不是原生脚本独立验收，也没有验证胜利后连续进入下一关。
- 未完成：原生后端全流程、自动设置导航及通关结算的完整实机验收。界面更新、不同 GPU/显示器、过小窗口等仍可能触发暂停。
