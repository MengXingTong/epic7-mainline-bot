# STOVE PC 实验性使用说明

**不需要全屏。PC 原生后端仍处于实验阶段，默认禁止输入；尚未完成原生采集/输入与完整新关结算的实机验收。**
目前完成了离线护栏、几何映射测试，以及通过桌面工具取得的私有 PC 地图截图识别。它们不等于无人值守运行已经验证。

## 窗口和分辨率

- 读取实际游戏客户区（`GetClientRect` + `ClientToScreen`），不把标题栏、窗口边框、桌面或显示器尺寸当作游戏内容。
- 客户区图像归一化为 1600×900 用于现有 OCR/状态机；输入按本轮客户区尺寸和屏幕原点反向映射。1600×900 是内部坐标系，不是要求用户使用的分辨率。
- 原生调用使用线程级 per-monitor DPI 坐标；不额外乘一次 DPI，避免 125%/150% 缩放时点位偏移。不修改系统缩放、代理或安全设置。
- 支持负坐标的副屏。截图后若窗口移动、缩放、DPI 改变、失焦、被遮挡或进程重启，拒绝该次输入；不会为了点击而自动抢焦点或强制全屏。
- 默认只接受 16:9 客户区。其他比例需经过本机验证后才可显式启用 `allow_stretched_client`；并非所有宽高比都已适配。超宽显示器仍可使用普通 16:9 游戏窗口。
- 小于 640×360 **物理客户区像素**时暂停；建议将普通窗口开到 1280×720 或更大以提高 OCR 可读性，不需要占满屏幕。尺寸达标也不能替代关卡/资源校验。

离线几何测试覆盖 640×360 至 3840×2160、96/120/144/168/192 DPI，以及正/负多屏原点；这验证坐标计算，不代表在每种真实显示器上都进行了游戏测试。

## 配置和已有进度

1. 源码安装依赖的方法同 MuMu 版。Windows 原生接口使用标准库 ctypes，不需下载输入驱动。
2. 将 `config.pc.example.json` 复制为 `config.pc.local.json`（已被 Git 忽略）。
3. 在本机填写：
   - `data_dir`：**同一账号、同一服务器原有运行目录**，其中必须已有完整 `state.json`。直接复用，不复制出空历史，不覆盖 Android `config.json`。
   - `pc.game_exe`：已安装 `EpicSeven.exe` 的完整路径。
   - `pc.server`：要操作的服务器名称；不能只看 Rank 推断服务器。
   - `pc.account_id`：该服务器的账号编号，使用字符串。不是昵称，不是 STOVE 会员编号。
4. 保持 `experimental_input_enabled: false`，先只做只读检查。

目前 PC 版不提供“忽略已有进度重新开始”的入口，也不自动创建空账号状态。不同账号/服务器必须隔离，不能让错误的历史绑定到别的角色。首次显式启动会显示数据目录、服务器/账号及旧通关摘要，要求用户确认历史归属；核验通过后保存绑定，已有绑定不允许自动改写到另一个角色。

## 只读检查

手动进入游戏的设置 → 账号信息页，使服务器名称及“服务器账号编号”完整可见，然后运行 `PCCheck.cmd`。命令会留出默认 7 秒让用户把游戏前置；也可以自行运行：

```powershell
py -3.12 -B -X utf8 pc_launcher.py check --delay 12
```

只读实例不能授权为输入实例；即使已有 STOP 标记，也只读预览，不移除 STOP、不按键、不入场、不修改进度。预览及账户核对证明只写入本机 `.local/pc-check/`，不要转发该目录。

## 实验性启动与停止

在确认本机原生截图、客户区映射、正确账号和风险以后，才考虑在本地设置 `experimental_input_enabled: true`。**这不是推荐未经观察直接挂机。**

- `PCStart.cmd`：输入 `PC START` 后，再将游戏停留在正确账号信息页并前置；精确核验服务器/编号后，仅返回大厅，启动共享核心状态机。
- `PCResume.cmd`：明确输入 `PC RESUME`。有失败或未结算 active 记录时拒绝启动；不通过删除记录或重刷修复。
- `PCStop.cmd`：向共享运行目录写 STOP，只停止脚本输入，不退出游戏。
- MuMu 与 PC 使用同一组 supervisor/worker 锁，不能同时运行两个账号写入者。

启动证明会绑定游戏窗口、PID、进程创建时间和账号/服务器。初次启动时证明过期或目标变化会拒绝输入；原生初始化失败会保留历史并记录安全暂停，不反复重连抢焦点。

## 人工补过后的核对

若 active 关卡已经由用户手动通过：

1. 在账号信息页执行 `check`。
2. 120 秒内手动返回地图，精确选中原 active 关卡，确认有绿色通关勾。
3. 执行 `py -3.12 -B -X utf8 pc_launcher.py reconcile`，再把游戏前置。
4. 输入 `PC CLEARED` 确认补记；这一步只写历史，不产生游戏输入，也不解除停止。
5. 需要继续时重新核对账号，再用 `PCResume.cmd`。

原失败 attempt、旧证据与其他通关记录都保留。没有绿色勾、关卡不一致、窗口/账号证明变化或后台写入者仍在运行时，拒绝补记。

## 当前限制

- PC 原生 GDI 截图、SendInput 和完整战斗/CG/结算链路仍需本机现场验收；当前没有宣布全量兼容或保证成功。
- 纯几何/模拟 API 单元测试不能发现所有 GPU 渲染差异、驱动限制、系统遮罩或游戏界面更新。
- 游戏必须可见且处于前台；不保证在最小化、被遮挡或用户同时操作时运行。
- 不处理密码、验证码、认证或安全权限提示，不绕过游戏/Windows 的输入阻挡。
- 不购买体力、不付费续战、不自动重试旧关。任何结果不明的已入场关卡都不能再次入场。
