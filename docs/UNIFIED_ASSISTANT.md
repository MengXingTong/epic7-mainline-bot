# 统一推进助手 — 当前实现

## 同一个软件

`Assistant.cmd`、`Start.cmd`、`PCStart.cmd`进入同一Tk界面；内部worker按所选任务调用原规划器和共用后台，不拆分用户操作入口。当前任务选择：

- **推进剧情关卡**：原mainline配置值保持兼容；大厅默认主线，已打开的兼容旧版支线直接按当前剧情推进。
- **普通深渊**：只使用上方普通入口，不进入下方高难度。
- **圣女3-7**：在已解锁并打开《圣女追悼文》的前提下，从当前进度推进至3-7，成功结算后仅循环3-7。

新安装默认剧情关卡；保留使用者已保存的任务选择。任务选择和客户端选择互相独立，唯一客户端可自动填入，多目标必须手选。

## 平台与授权

MuMu用ADB，不需模拟器在Windows前台；模拟器内部保持目标游戏。PC只用PrintWindow和后台窗口消息，不移动系统鼠标、不激活游戏，不使用SendInput作为回退，不支持最小化。

当前源码的 MuMu 发现直接绑定实例当前前台应用的实际包名，不要求默认包名、渠道包名单或安装查询。请先打开游戏再刷新，实例标签会显示当前应用包名；页面识别仍须通过才会输入。管理器只辅助命名和提供连接端口，不再凭 PID/启动状态字段或条目缺失过滤已在线的本地实例；连接尝试后以 ADB 在线状态为准。开始后切到其他应用仍停止输入，不自动换绑。渠道服目前只有离线模拟验证，尚未实机验收；更新须退出旧助手/worker后加载新源码或新包。

启动器每次申请标准管理员权限，已提升则不重复申请；UAC由使用者本人操作，软件不绕过或代点。无需账号或服务器OCR，不导航账号页，也没有“仅观察”和前台模式开关。进度归属由使用者选择，不自动识别换账号。

窗口句柄、进程寿命、客户区几何、帧新鲜度、STOP和并发历史锁仍需成立。API投递成功不等于游戏接受，导航后读取新画面，真正消耗体力前核对准备页。

## 剧情与历史

主线使用原attempted/completed/active/last_cleared；旧版剧情使用story_progress.books命名空间。原主线进度不会因新任务或布局兼容被清空、替换或伪造。

新开始从当前画面接续，不回看旧失败关核查；原主线旧active完整归档而非冒充成功。当前剧情未结算active继续对应战斗/出口流程，不能通过重载worker重新入场。每次独立入场必须先保存证据和意图。

圣女3-7成功结算是唯一重复例外，每次新建独立记录；战败、结果不明或其他已尝试关不能重复。地图标题和紫色剧情指针都不是充分选中证据：点击节点图标，准备页完整编号确认后才消耗体力。

## 后台地图与地区

旧地图会平移，使节点移出画面。用当前识别到的标签建立相对地图缓存，后台有界拖动查找；拖动过程中持续检查目标、几何和停止请求，异常总是释放原按钮。跨地区使用原生已解锁“往下一地区”入口并保存路线；三个地区总览卡片与具体关卡地图分开识别，不凭N+1猜测不存在的关卡。

免费教学、剧情跳过、三/五波CLEAR、蓝色虚线出口及结算是不同状态；关闭CLEAR不是成功记录，独立结算证据才计为通关。

## 持续运行与维护

无关数/层数上限；旧limit忽略，不保留隐藏30。暂停可继续，停止后可再次开始；不会关闭游戏、清空进度。体力不足的剧情准备页等待自然恢复，不购买/兑换；容量和未知业务提示进入可恢复等待，不误判为战败。

`assistant_control.py`的status/pause/resume/stop只针对当前run；restart由现有GUI消费带expected_run_id的维护指令，先优雅停止worker，退出后才启动新worker。运行期间不直接并行启动另一套脚本。

### 容量处理后继续原任务

“处理后继续”保持同一任务/run，不必重新开始。仅完整独立容量拒绝与原唯一未接受入场来源一致时，记录本次明确继续命令及来源哈希；下一周期重新核对实例/几何与当前画面。缺地图链的完整已知队伍/辅助页先预存原生返回意图，逐级回地图重验，再接续首次实际入场。原地图凭据不过期续命，返回消息不等于地图身份或完成。

仍停留在同一容量弹窗时按同一拒绝处理，不创建第二条许可；新的独立容量拒绝需要新的“处理后继续”，而不是新的run。每条入场意图发送前消费对应继续记录，失败/不明/明确未发送也不复用；真实战斗/剧情接受、战败、资源提示和未知覆盖层保持优先。没有完整拒绝证据不从sent/等待超时生成重发权限，不自动整理或扩容。

本项28项离线生成页/伪后端回归通过；未对活着的旧worker热更、重载或发送实机输入，PC各渠道仍按各自未验收范围标注。

## Steam / STOVE 电脑客户端

统一选择项仍为“电脑客户端”，实例标签按已核实的精确游戏进程区分 Steam / STOVE，并保留实验性标记。Steam 使用 `EpicSeven_Steam.exe`，STOVE 使用 `EpicSeven.exe`；两者共享PC任务后端，历史配置名 `stove_pc` 保持兼容，不新增独立空进度或自动推断账号。Steam启动器、网页进程及覆盖层不作为游戏目标。

先自行完成登录/服务器选择，再按当前画面开始。Steam本机失焦1280×720窗口的只读发现、后台采集和OCR已核验；游戏内输入接受和任务结算未验收，未最小化以外的场景不扩大支持。细节见 `STEAM_VALIDATION_2026-11-09.md`。本项收录v1.4.16预览包，不改写旧版附件，旧进程须退出重启。

## 验证边界

PC后台能力仍为实验性，并非所有电脑均支持PrintWindow或窗口消息。MuMu旧版剧情本轮未实机验证；其他历史支线不承诺通用支持。最新实机位置、跨章与循环证据见`STORY_VALIDATION_2026-11-03.md`；历史各版回归见CHANGELOG及原发布记录。

分享包只含允许的源码、运行库和通用小图块，不含本机截图、OCR、日志、账号、设备绑定或进度。只分享干净ZIP，不分享用过的目录。

## 中文界面与提示

统一界面的标题、场景名称、状态说明、安全报错，以及命令行帮助、参数校验、旧版确认提示和离线自检说明均使用中文。场景内部代码仅在展示时转换；配置键、命令参数、进程名、文件路径、原始识别标签和状态协议保持不变。旧版维护工具改为提示输入“开始”“继续”“已通关”或“确认”，同时兼容原英文确认词；不会增加统一界面的确认步骤。

源码更新后需重新启动助手才能加载新文案；已经生成的离线包不会被自动改写。第三方名称、许可原文、游戏自身画面文字及原始诊断数据不作翻译，也不改写已有进度或证据。此次修改仅为中文展示，不扩大实验性桌面端的支持或实机验收范围。
